# Architecture decision record (proposed / approved direction)

## Approved direction from conversation
- Separate private repository, independent of the family dashboard and other Cypress Forge projects.
- Vendor-neutral platform with OpenWrt as first adapter; avoid coupling UI to vendor protocols.
- Read-only collection first; no router configuration changes during baseline observation.
- Responsive web interface supporting phone and desktop.
- Free/open-source, existing hardware first.
- Keep confirmed topology distinct from inferred and manually entered links.
- Preserve future options for resale, white-label, and licensing.

## Licensing (decided 2026-11-18)
- Open core: this repository is MIT-licensed (see LICENSE).
- Paid features ship as a separate, closed add-on that is never committed here.
- Dependency licenses checked: all permissive (MIT, BSD, ISC, Apache-2.0).
- Free vs paid split (decided 2026-11-18):
  - Free: live status, ports, firewall, DHCP/DNS; 7-day history; one router; themes.
  - Paid add-on: history beyond 7 days plus export; alerts (WAN drop, new device, router offline); multi-router; authenticated phone access on the LAN.
  - Do not start selling until the paid add-on has at least long history and alerts.
- Add-on license check (decided 2026-11-21): a signed offline license file, checked locally with no network or
  activation. Without a valid license the add-on records history and alerts but does not send alerts anywhere.
  Core itself never checks licenses. Long history and alerts shipped in add-on release 0.2.0 (see docs/ADDON-DESIGN.md).

## Proposed, not implemented
- React/TypeScript frontend; FastAPI backend; SQLite storage.
- SSH/ubus adapter for OpenWrt, SNMP/LLDP later.
- Local Windows workstation as initial collector host; no application on MX64.
- Localhost-only development; authenticated LAN access after review.

## Non-goals for first release
- Network configuration writes, firmware management, RMM, remote control, cloud SaaS, multi-tenant MSP features, automatic full-vendor support.

## Open questions
- Location and quality of source code generated by the separate Work session.
- Exact data model, authentication design, mobile access approach, and collector permissions.
